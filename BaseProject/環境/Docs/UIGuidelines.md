# UI の作り方の決まり

UI(`App::Object::UIBase` の系統)を作るとき・整理するときの決まり。
コードの中身は `Source/Application/Object/UI/` の各ヘッダーにある。ここは「どう作るか」の判断だけを書く。

---

## 1. UI 1つの中身

UI 1つは次のものを組み合わせてできている。

| 部品 | 中身 | 置き場所 |
|---|---|---|
| アンカー(UIAnchor) | 位置・大きさ・回転・倍率・色・Z順・湾曲 | `UI/Core/UIAnchor.h` |
| 飾り(Decoration) | 板ポリ・画像・文字。配列で何枚でも重ねられる | `UI/Decoration/` |
| 反応(UIInteraction) | 当たり判定・押下・音・項目移動。カーソルを遮る UI だけが持つ | `UI/Core/UIInteraction.h` |
| 演出(UITransition) | 出し入れ(show / hide)と合図(pulse) | `UI/Core/UITransition.h` |
| マテリアル(UIMaterial) | 飾り全部に掛ける効果(ディゾルブなど) | アセット |

- **見た目は必ず飾りで作る。** 画像・文字・板ポリはどれも飾りの種類で、UI のクラスではない。
- **当たり判定は UI 1つにつき1枚だけ。** 押せる場所を増やしたいときは UI を増やす。

---

## 2. クラスの決まり

**クラスは役割(振る舞い)で切る。見た目の名前のクラス(画像 UI・文字 UI など)は作らない。**

| クラス | 使うとき |
|---|---|
| `UIElement` | 振る舞いを持たないもの。背景・ロゴ・見出し・窓・入れ物。カーソルを遮るか(BlockCursor)は1つずつ決める |
| `UIButton` | 押されて何かをするもの |
| `UIGauge` | 値を出すもの(HP・音量など) |
| 各 HUD | ゲームの状態を読んで出すもの(照準・ロックオンなど) |
| `SideMenu` / `OptionHUD` など | 自分の処理を持つ部品 |

- 新しいクラスを足すのは、**そのクラスにしかない処理があるとき**だけ。見た目の違いは飾りで作る。
- 以前の `UIImage` と `UIPanel` は `UIElement` にまとめた。古いシーンは読み込み時に読み替わる。
  - `UIImage` → BlockCursor あり(以前は押せる UI だったため)
  - `UIPanel` → BlockCursor なし

---

## 3. 親子で伝わるもの

UI を別の UI の下(子)に置くと、次のものが親から伝わる。

| 伝わる | 伝わり方 |
|---|---|
| 位置・回転・倍率 | 親の行列に追従する。アンカーの値は**親から見た値** |
| Z順(layer) | 親の Z順 + 自分の Z順 |
| 表示 | 親が隠れていれば子も出ない(押せない)。UI でない親(進行役など)の表示にも従う |
| 消える演出 | 親が hide を流している間は子も描かれ、親の濃さで一緒に薄れる |
| HUD の隠し | 親が HUD として隠れていれば子も出ない |

伝わらないもの : 大きさ・色・マテリアル・湾曲・触れるか(Interactable)。

- 画面での値が要るときは `CalcWorldAnchor` / `GetWorldPixelPos`、画面の座標で置くときは `SetWorldPixelPos` を使う。
  `m_anchor.pixelPos` を画面の座標として読み書きしないこと。
- 親だけを隠して子を出すことはできない。別々に出し入れしたいものは、親子にしない。

---

## 4. 別の UI にする条件

**次のどれか1つに当たるものだけを別の UI(子)にする。どれにも当たらないものは、親の UI の飾りにする。**

1. **カーソルを扱う** : 自分で押せる、またはカーソルを遮る(裏の UI を押させない)
2. **単独で出し入れする** : 親とは別に出したり隠したりする
3. **自分の演出を持つ** : 自分だけの show / hide / pulse を流す
4. **コードが動かす・書き換える** : 位置・大きさ・中身(文字や画像)をコードが毎フレーム、または場面ごとに変える
5. **他から GUID で指される** : 進行役・ボタン・項目移動などが、この UI を名指しする
6. **見た目の設定が親と違う** : 別の UIマテリアル・湾曲・スキャンライン・HUD の設定を持つ
7. **振る舞いを持つクラス** : UIButton・UIGauge・HUD など(UIElement 以外)

### 当てはまらないもの(飾りにする)の例
- ボタンの裏の板、窓の枠、見出しの下線、入れ物の背景
- どこからも名指しされず、いつも親と一緒に出入りする画像・文字

### 飾りへまとめる手順
エディターの GameObjectHierarchy で、まとめたい UI を右クリック → **Merge Into Parent**。

- 条件に当たっているときはメニューが押せず、理由が出る。
- 飾りは画面での見た目が変わらないよう、親から見た値に直して親の飾りの末尾へ足される。
- まとめた UI の下にあった UI は親へ付け替わり、まとめた UI は消える。
- 旧 `UIImage` は BlockCursor が立っているので、遮る必要が無ければ先に切ってからまとめる。
- 押せる親へは、反応(Reaction)を持つ飾りをまとめられない(親の状態で動き出してしまうため)。

## 5. 同じ形を繰り返すもの

設定の行(ラベル + 値 + `<` `>`)、スクロールバー、ステータスの行のように、
**同じ組み合わせを何度も作るもの**は、飾りを番号で書き換える形にも、毎回手で組む形にもしない。
1つ組んだらプレハブ(ObjectPrefab)にして、2つ目からはプレハブを置く。

### プレハブの決まり
- **置いた時点で写すだけ。** 置いたものは元のアセットとつながらない(アセットを直しても、置いた分は変わらない)。
- **置くのはエディターだけ。** コードは実行中にプレハブから出さない。
  コードが決めるのは「出すかどうか」だけで、「どれを出すか」はエディターで置いて GUID で指す。
- 1つの部品は、根の UI の下にまとめてからプレハブにする(行なら、行の UI の下にラベル・ボタンを置く)。
- 中どうしの参照(親・項目移動の前と次など)は、置いたときに新しい GUID へ付け替わる。
  中に居ない相手への参照はそのまま残るので、置いたあとに指し直す。
- 根の位置・回転・倍率・Z順は、置いた先の親から見た値としてそのまま使われる。

### 操作(GameObjectHierarchy)
| したいこと | 操作 |
|---|---|
| プレハブにする | 根にしたいものを右クリック → **Save As Prefab**(名前を入れて Save。`Asset/ObjectPrefab/<名前>.ojobjprfb`。同じ名前は上書き) |
| 根へ置く | **AddObject** → From Prefab |
| ある UI の下へ置く | 親にしたいものを右クリック → **Place Prefab Here** |

## 6. 見た目のプリセット(UIPreset)

**同じ見た目の飾りを何か所にも置くときは、飾りをプリセットにつなぐ。**
プリセットを直すと、つないでいる飾りが全部変わる(プレハブと違い、つながったまま)。

- プリセットは飾り1つぶんの見た目。置き場は `Asset/UIPreset/`(`.ojuipreset` / `.obuipreset`)。
- 飾りは「付いていく部分(Follow)」を選ぶ。付いていく部分はプリセットの値になり、ほかは飾りの値のまま。

| 部分 | 中身 | 既定 |
|---|---|---|
| LOOK | 種類・色・枠と UV(板ポリ・画像)・フォントと文字の組み方(文字) | 付いていく |
| SIZE | 大きさ・倍率・ピボット | 付いていかない |
| REACTION | カーソルへの反応 | 付いていく |
| ANIMATION | トゥイーン・揺れ | 付いていく |
| CONTENT | 文字列・画像のテクスチャ | 付いていかない |

- 位置・回転・Z順・名前・表示・番号は、いつも飾りの値(プリセットからは来ない)。
- 付いていく部分は、飾りのインスペクターでは触れない。直すときは次のどちらか。
  - アセットのインスペクターでプリセットを開いて直す
  - 飾りのインスペクターで **EditPreset** を立てて直す(直した値がプリセットへ書き戻される)
- 直したプリセットは保存するまでファイルに残らない(Save Asset / Save Preset)。
- コードが中身を書き換える飾り(進行役が文字を入れるなど)は、CONTENT を付いていかせないこと。

### 操作
| したいこと | 操作 |
|---|---|
| 飾りからプリセットを作る | 飾りのインスペクターの Preset 欄で名前を入れて **Save As Preset**(そのままつながる) |
| 空のプリセットを作る | AssetDataBase の作成メニューで UIPreset |
| つなぐ | 飾りのインスペクターの **Preset** でプリセットを選ぶ |
| 切り離す | **Unlink**(今の見た目のまま残る) |

---

## 7. Z順

- 子の Z順は「親の Z順 + 自分の Z順」。子を親の手前に出すなら、子の layer を正にする。
- 飾りの Z順は「UI の Z順 + 飾りの layerOffset」。
- カーソルの取り合いは画面での Z順(親込み)で比べる。手前の1つだけが反応する。

## 8. コントローラー用の飾り

**キーボードとコントローラーで絵を変えたい UI(押すボタンの絵など)は、UI を2つ置かずに、コントローラー用の飾りの組を持たせる。**

- 飾りの組は2つまで : 既定(キーボード・マウス)と、コントローラー用(任意)。
- コントローラー用を持つ UI は、最後に触ったデバイス(`InputDeviceManager::GetActiveDevice`)がコントローラーの間だけそちらを出す。持たない UI はいつも既定の組。
  - 見るのは実際に触ったデバイスだけ。キーボードで項目移動(Tab・矢印)をしても、出す絵はキーボードのまま。
  - まだ何も触っていないときはキーボードとみなす。
- 判定の大きさ(飾りの範囲から作る場合)も、出している組で測る。
- コントローラー用は既定の組の写しから作るので、**同じ役の飾りは同じ番号(id)を持つ**。ゲージの中身・値の文字などを番号で指しているクラスは、そのまま出し分けられる。番号を変えないこと(消して作り直さず、写した飾りを直す)。
- コードが一度だけ書き込む値(ウェーブの見出しなど)は、`UIBase::ForEachDecorationSet` で両方の組へ入れる。毎フレーム書く値は、出している組へ書くだけでよい。
- どちらかが組を2つ持つ UI は、親の飾りへまとめられない(Merge Into Parent)。

### 操作
| したいこと | 操作 |
|---|---|
| 作る | 飾りの一覧の **Add Gamepad Decorations**(今の飾りの写しができる) |
| 編集する組を選ぶ | 一覧の上の **Keyboard / Gamepad**(選ぶと表示もその組になる) |
| 確かめる表示 | **Preview**(Auto は実行時と同じく最後に触ったデバイスに従う。保存しない) |
| 外す | **Remove Gamepad** を Ctrl+クリック |
